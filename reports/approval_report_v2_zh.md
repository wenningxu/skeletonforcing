# 方案 v2：保留冗余运动特征与 UMT5，首先进行过拟合验证

**2026-09-23｜待审批｜替代 v1；v1 的 XYZ/GloVe 训练入口已禁用。**

本次没有创建或启动 GPU。保留此前的逐次审批要求；此前 US$500 总预算不是本次运行的批准。

## 1. 本次更正

v1 同时改变动作表示、文本条件和时间场，难以辨别性能差异来源，也没有先验证模型能否记住训练动作。新的顺序是：核实并保留成熟运动特征 → 复用真实 UMT5 编码 → 本地结构验证 → 经批准的单动作过拟合 → 再申请多动作过拟合与正式实验。

用户随后允许“类似结构但更适配”的表示，并要求保留速度、旋转和 root。因此本报告提出 **266D**，不是回到纯 22×3 XYZ，也不是通过 VAE 编码为潜变量。

## 2. FloodDiffusion 原始表示核对

本地依据：`third_party/FloodDiffusion/configs/vae_wan_1d.yaml`、`models/vae_wan_1d.py`、`utils/motion_process.py`。

其 VAE 输入为 HumanML3D 的 263D 特征，读取 `new_joint_vecs`，使用数据集 `Mean.npy/Std.npy` 标准化。263 个通道为：

| 部分 | 维数 | 原始索引，左闭右开 |
|---|---:|---|
| root 角速度、局部 XZ 线速度、root 高度 | 4 | `[0,4)` |
| 除 root 外的根相对关节位置 RIC | 63 | `[4,67)` |
| 21 个非 root 关节的 6D 旋转 | 126 | `[67,193)` |
| 22 关节的局部线速度 | 66 | `[193,259)` |
| 脚接触 | 4 | `[259,263)` |

这些冗余量携带姿态、运动和接触结构。不能只留下 XYZ 后把其余信息的损失归结为调度效果。保留通道沿用原始单位与定义，速度段为数据表示中的每帧差分，不擅自乘 FPS 改写其尺度。

一个代码细节：VAE 配置中名为 `vel_window=[4,67]` 的附加损失实际上作用于 RIC 位置段。复用时按真实通道含义理解，不能仅凭变量名把它当成局部速度损失。

## 3. 推荐的 266D 表示及其代价

| 部分 | 维数 | 新索引 |
|---|---:|---|
| 原 root 特征，全部保留 | 4 | `[0,4)` |
| 包含 root 的显式全局关节 XYZ | 66 | `[4,70)` |
| 原 6D 旋转，全部保留 | 126 | `[70,196)` |
| 原局部线速度，全部保留 | 66 | `[196,262)` |
| 原脚接触，全部保留 | 4 | `[262,266)` |

只用 66D 世界位置替换 63D RIC；另 200 维逐值保留，维度增加 3。这里“世界坐标”指 HumanML3D 已规范化的全局坐标系，不是未经坐标变换的任意外部场景坐标。

**理由**：固定 RIC 位置不能独立固定世界位置，因为世界位置还取决于 root 旋转和历史 root 位移积分。显式世界位置让根关节与其他关节的空间控制都有直接对应的通道，固定谷底不再依赖尚在去噪的 root 轨迹。

**代价**：表示中的 root 高度/速度、全局位置、局部速度和旋转可能互相矛盾。不得通过只展示 XYZ 控制点来掩盖这种矛盾。新代码分别测量这些不一致；训练附加 root/线速度一致性损失，但目前没有强制所有旋转都与位置严格一致的求解器。

动作输出以 66D 位置块为权威。若以后用旋转驱动 FK 骨架，不能默认 FK 后仍然严格满足这些位置控制；必须额外验证或求解。

归一化：保留 200 个未改动通道的官方统计量；新增 66D 坐标统计只从训练数据估计。**单动作过拟合阶段**只用被选训练片段估计这 66D 的均值/方差并设置 0.05 m 标准差下限。它只是调试统计，不得用于宣称全数据集泛化；正式训练重新仅用 train 估计。

### 与 263D 评测接口的关系

已实现确定性 `263→266` 与 `266→263` 适配。后者根据显式 XYZ 与生成的 root 朝向重建 RIC、root 高度、root 线速度和局部线速度，保留预测的 6D 旋转、角速度和脚接触。最后一帧缺少下一帧的位置差，保留其原预测速度。

此导出会改写冗余速度以匹配显式位置，因此必须在导出前报告原始冗余分支的误差，不能只看导出后的指标。坐标控制误差在原始 266D 的位置块上计算。正式质量评测还需用真实数据验证转换底线。

263D 的原始通道布局也保留为参考实现，后续可做表示消融；本次只申请 266D 的过拟合，不把它描述为完全未经改动的 FloodDiffusion 表示。

## 4. 文本：复用 UMT5-XXL，不再使用平均词向量

已核对 `models/diffusion_forcing_wan.py` 与 `models/tools/t5.py`：

- 使用同一个 `T5EncoderModel` 实现、官方发布的 `models_t5_umt5-xxl-enc-bf16.pth` 权重；
- 使用对应的 `google/umt5-xxl` tokenizer；
- 同样使用 512 token 上限、whitespace 清洗、special tokens 与 padding mask；
- 保留每个有效 token 的 **4096D** 上下文特征，不做均值池化；
- 编码器冻结，输出缓存至私有磁盘；缓存保留模型权重和 tokenizer 文件校验值；
- 动作模型通过 cross-attention 读取 token 序列。

缓存与在线重新计算使用同一冻结编码器；缓存不是弱化的文本模型。编码完成后释放 UMT5 GPU 内存，再训练动作网络，减少同时占用的显存。实际峰值尚未测量，不能预先保证无 OOM。

唯一上游兼容补丁：把 Python 函数定义时就调用 CUDA 的默认设备改为 CPU；实际编码显式传入 CUDA。没有改 tokenizer、权重结构或前向计算公式。

当前的动作 cross-attention 骨干仍是为关节—时间场编写的分轴网络，不声称整个 Wan DiT 已原样复现。

## 5. 你询问的四种输入是什么

它们都是内部模型条件，不需要用户额外标注四份数据。

| 输入 | 含义 | 来源 | 是否含未给定的真实动作 |
|---|---|---|---|
| 控制标志 `M` | 哪些特征必须保持为观测值 | 用户控制点映射到通道的布尔掩码 | 否 |
| `σ` | 当前每个特征还剩多少噪声 | 本次采样的完整结构化时间场 | 否 |
| 关节索引 | 当前 token 属于骨盆、手腕或其他关节 | 固定骨架布局，内部生成的身份 embedding | 否 |
| 帧索引 | 当前 token 的时间位置 | 窗口内位置编码，内部生成 | 否 |

控制标志不能简单由 `σ=0` 替代：已知控制点和去噪结束的生成点都可能干净，但只有前者是永久观测。

模型把 266 维**无损重排**为 22 个关节组，每组最多 13 个通道；补齐位置不作为真实数据。模型末端逆重排回 266D，测试确认所有通道恰好出现一次。这里的线性输入投影是 Transformer 的 token embedding，没有训练一个独立动作编码器或压缩潜空间。

网络同时接收每个组内的逐通道 σ 和观察掩码，因为“已知手腕位置”不等于“已知手腕旋转、速度和接触”。

## 6. 永久无噪声谷底与精确时间场

沿用骨架距离与时间距离构建 `d(t,j)`，先计算传播延迟 `a=ρd/(1+d)`，再在 `p_k=k/K` 上计算：

\[
\sigma_k=1-\operatorname{clip}((p_k-a)/(1-a),0,1),\qquad K=32.
\]

首轮 `ρ=0.75`，时间尺度 20 帧，骨架尺度 2 条边。训练与推理调用同一份函数，抽取的是**完整采样轨迹的一步**，绝不各自随机采样关节/帧的噪声水平。

对被控制的 XYZ 通道，额外强制 `σ=0`，加噪时直接放入观测值，初始化与每一步输出都保留观测值。对同一关节的未知旋转/速度通道，不因为观测到了位置就错误地设置为干净真值：它们从噪声开始，只是去噪可以更早。

所以“谷底无噪声”的严格对象是**已观测的量**。如果只给了位置，就不能把该关节其他属性的真实值偷偷作为模型输入。

归一化空间中控制通道逐位保持不变。反归一化输出时再次拷贝原始物理控制坐标，消除浮点往返舍入。与此同时还测量这次拷贝前的物理误差，防止用末端修补掩盖逐步实现错误。

## 7. Rollout 训练与监督目标

### 为什么要改目标

直接加噪的训练状态为 `xσ=(1−σ)x0+σε`，此时 `ε−x0` 是正确的解析流目标。

但真实 rollout 后，`xk` 是模型先前预测的结果，通常已经不在这条给定 `x0,ε` 的直线上。继续把最初的 `ε−x0` 标在这种状态上并不正确。

### 当前实现

预测目标改为干净的完整动作特征 `x̂0`。对 `σ>0` 的活动位置，推理执行：

\[
v_k=(x_k-\hat x_0)/\sigma_k,
\quad x_{k+1}=x_k+(\sigma_{k+1}-\sigma_k)v_k.
\]

非活动位置不更新，所有观测通道每步固定。这个更新与线性路径的 x0 参数化一致，但不把使用模型状态的附加监督声称为无偏的原始 flow-matching 目标。

单动作验证的训练安排：

1. 前 200 次优化使用同一采样时间场上的直接加噪状态，先学会基本去噪。
2. 此后 50% 优化步使用真实模型 rollout：从随机噪声开始，执行前 k 步，每次消费上一步产生的状态；不在中途用真实动作重置。
3. 另 50% 保留相同时间场上的解析加噪样本，以帮助稳定训练。
4. rollout 最后至多 4 步保留梯度，更早部分 no-grad，即明确的截断反向传播；当前第 k 步对干净目标作监督。
5. 损失只对当前实际去噪的未知有效通道计算重建 MSE；另以 0.01 权重加入 root 高度、root 线速度与局部速度的一致性损失。

推理全程只使用模型上一步输出、文本和给定控制点，不访问未知真实动作。

这里实现的是**去噪步骤的 rollout**，不是已经完成了无限长流式窗口的自回归训练。帧窗口滚动、历史冻结和新增未来条件仍须另行设计验证。

| 项目 | 设置 |

## 9. 如何判断是真过拟合

主要依据是新噪声种子下的 **完整 32 步 rollout 重建**，不是 teacher-forced 损失下降。

所有 4 个测试噪声种子都须满足以下调试门槛：

| 项目 | 初始门槛 |
|---|---|
| 未观察通道标准化 MSE | < 0.01 |
| 未控制关节 MPJPE | < 2 cm |
| 控制点物理最大误差，末端物理拷贝前 | < 1e-6 m；同时每步归一化控制值精确不变 |
| 6D 旋转标准化 MSE | < 0.01 |
| 局部速度标准化 MSE | < 0.01 |
| 动作速度误差/静止姿态基线误差 | < 0.25，防止靠静止平均姿态过关 |
| 退化 6D 旋转 | 0 个 |
| 旋转 FK 与显式 XYZ 分歧 | 不超过真实动作自身该项分歧 + 2 cm |

还独立报告 root 轨迹误差、骨长误差、root 高度和两类线速度自一致性。FK 骨长采用参考动作首帧估计，用于评测诊断，不把参考骨架信息偷偷喂给采样器。

真实数据中旋转与位置也可能并不完全一致，所以同时报告 GT 的 FK 误差底线。这些阈值是预先定义的实现诊断标准，不是论文常用 benchmark 标准。如果失败，保留结果并定位问题，不事后放宽阈值把失败改成成功。

单条动作不计算 FID/R-Precision，也不报告多样性与 SOTA 比较，它们在此场景没有合适的统计意义。

## 10. 已完成的本地验证与尚未验证项

已完成 CPU 单元测试：263/266 无损打包；保留原 root/旋转/速度/接触通道；266→263 后恢复显式 XYZ；位置观察不泄漏其他特征；共享离散时间场；每步控制不变量；解析正确预测器恢复；rollout 确实消费前一步状态；截断梯度存在；文本 padding 不泄漏；有效 token 能影响输出；一致性损失反向传播；审批记录缺失时拒绝运行；FK 诊断与 GT 基线比较。

这是宽度32/深度1的合成结构测试，不是拟申请的12.33M模型、32步采样或真实动作实验。CPU 全部 **14 项单元测试通过**。最新合成结果与前一次失败记录分别写入 `reports/cpu_overfit_v2.json` 与 `reports/cpu_overfit_attempts.json`。

尚未验证：完整 UMT5 checkpoint 加载与实际峰值显存、真实动作 overfit、真实数据 263/266 往返误差、模型重复生成的稳定性、正式质量与实时性。此前网络卷上的数据未完成核验，不会假称数据就绪。
