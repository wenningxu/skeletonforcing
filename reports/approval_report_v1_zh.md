## 2. 研究问题与可证伪假设

目标是在任意给定帧、任意给定关节的三维位置约束下生成其余动作，并研究能否扩展到流式生成。

需要区分两个命题：

1. **坐标约束命题**：所有指定关节帧始终等于输入控制坐标。这个性质通过保留观测变量实现，可通过代码不变量验证。
2. **生成质量命题**：在同样满足坐标约束时，以这些点为起点向时间和骨架周围传播去噪，比统一时间或仅时间调度生成更自然、更符合文本的动作。这个性质需要真实数据和对照实验，不能从“锚点零误差”推导。

因此，主要研究结论必须来自同等硬约束、同等模型容量和计算预算下的质量差异。仅展示零控制误差不能证明低谷调度有效。

本报告不接受“所有现有最好模型必然无法消除关键帧误差”作为已证实前提；允许硬约束的表示可以直接固定部分变量。我们关注的是满足约束后其余动作的合理性与效率。

## 3. 与 FloodDiffusion 的关系及区别

参考来源：

- 论文：[FloodDiffusion: Tailored Diffusion Forcing for Streaming Motion Generation](https://arxiv.org/html/2512.03520v1)。
- [官方代码](https://github.com/AlayaLab/FloodDiffusion)，检查到的 HEAD：`b611d6c4e24357a90066034935ed445179723b37`；下载归档另存 SHA256。
- [官方资产](https://huggingface.co/ShandaAI/FloodDiffusionDownloads)，查询到修订 `97fe404e1b52293b6c8db47619fa7ab9b5459405`。
- [HumanML3D 表示转换代码](https://github.com/EricGuo5513/HumanML3D)，修订 `9176e8fb446b71c7d2a725eb5cf6fec1ae3b3c23`。

| 方面 | FloodDiffusion | 本方案 |
|---|---|---|
| 扩散变量 | 因果 VAE 压缩后的动作潜变量 | 原始动作空间的 22 关节 XYZ |
| 动作编解码器 | 有 | 无 |
| 时间场 | 主要沿序列时间组织 | 帧索引 × 骨架关节的二维场 |
| 已知位置约束 | 非本论文的主要实验目标 | 每个指定关节帧为永久干净观测 |
| 骨干 | 潜空间 DiT | 空间与时间分轴注意力 Transformer |
| 文本 | UMT5 条件 | 首轮原型使用固定 GloVe 词向量均值 |
| 初期目标 | 高质量流式文本动作生成 | 验证关节—时间调度与硬约束的机制 |

继承的是“结构化时间场、训练与采样对应、缓冲区内部双向交互”的思路，不是直接微调其潜空间模型。首轮的小模型与简化文本条件不支持公平宣称优于 FloodDiffusion 的完整系统。

## 4. 动作变量与坐标约定

采用 `X ∈ R^(B×T×22×3)`，20 FPS，长度单位为米。关节拓扑使用 HumanML3D 的 22 关节骨架。

数据提供的 263 维动作特征通过官方确定性坐标恢复函数转为 XYZ。这个恢复是几何运算，不是学习型编码器。模型直接预测 XYZ 空间中的速度场，输出仍为 XYZ，整个生成链路没有 VAE、潜变量瓶颈、运动编码器或动作解码器。

训练片段将首帧根关节的 X/Z 平移到原点，保留竖直高度。控制点和目标动作使用同一坐标系。首轮不承诺直接输入未经转换的外部世界坐标；实际应用必须明确外部坐标到生成坐标的变换，不能用未提供的真实动作推断变换。

首轮每个控制点固定一个关节的三个坐标。不包含“仅固定某一个坐标轴”、旋转约束、接触约束或相互冲突约束的求解器。

## 5. 时间场：永久干净的谷底与向外扩展的去噪

定义 `M[t,j]∈{0,1}` 为控制掩码，`C[t,j]` 为指定 XYZ。定义噪声系数 `σ=1` 为纯噪声、`σ=0` 为干净；这与部分论文把进度方向反过来的记号不同，但含义一致。

### 5.1 骨架—时间距离

令控制点集合为 A，对非控制点定义：

\[
d(t,j)=\min_{(t_a,j_a)\in A}\left[\frac{|t-t_a|}{\tau_t}+\frac{d_G(j,j_a)}{\tau_j}\right].
\]

其中 `d_G` 是骨架最短路径边数。原型取 `τ_t=20 帧`、`τ_j=2 条骨架边`。这两个量决定时域和空间传播的相对尺度，属于待验证超参数。当前空间注意力允许所有关节交互；图距离体现在时间场中，并非限制注意力只能沿骨骼边传播。

### 5.2 去噪开始的延迟

\[
a(t,j)=\rho\frac{d(t,j)}{1+d(t,j)},\quad \rho=0.75.
\]

对非控制点，给定全局采样进度 `p∈[0,1]`：

\[
\sigma_p(t,j)=1-\operatorname{clip}\left(\frac{p-a(t,j)}{1-a(t,j)},0,1\right).
\]

对于控制点，直接规定 `σ_p(t,j)=0`，不套用非控制点公式。

这保证：

- 谷底从初始化开始就是干净观测，永不加噪。
- 所有未知点在 `p=0` 都从标准高斯噪声开始，避免“低噪声状态却拿标准高斯初始化”的边界错误。
- 距控制点近的未知点先开始去噪，远处开始得更晚。
- 所有未知点在 `p=1` 到达 `σ=0`。
- 每个点的噪声单调下降，不反复加噪。

这是“去噪起始前沿向外推进”，而不是让邻域在某一步突然变成新的精确观测；只有用户给定的控制点具有严格已知值。靠近谷底的未知点虽然较早变清晰，仍可能有预测误差。

## 6. 训练与采样的精确对应

### 6.1 共用离散采样轨迹

首轮固定 `K=32` 步，`p_k=k/K`。训练与采样共同调用 `trajectory_step(k,K,M,d,mode)` 获取完整的 `σ_k` 和 `σ_(k+1)`，不另写训练专用调度。

训练只随机选择一个全局索引 `k∈{0,…,31}`，然后取该步**完整的二维时间场**。绝不分别为每个帧或每个关节抽取独立噪声时间。

训练仍然需要随机样本、控制点以及高斯噪声；这些随机性不等于独立随机时间场。多种控制点布局各自对应一条可复现的采样轨迹。

当前代码要求评测的采样步数与检查点的训练步数设置一致。以后研究减少采样步数时，应明确列为新的步数分布或蒸馏实验，而不是默默改变评测轨迹。

### 6.2 加噪与监督

对未知坐标：

\[
X_k=(1-\sigma_k)\odot X_0+\sigma_k\odot\epsilon,\qquad \epsilon\sim\mathcal N(0,I).
\]

对控制坐标直接令 `X_k=C`。模型预测：

\[
v_\theta(X_k,\sigma_k,M,text)\approx \epsilon-X_0.
\]

流损失只监督有效帧中、非控制点且 `σ_(k+1)<σ_k` 的位置，即该离散采样步实际更新的位置。填充帧和永久谷底不进入流回归损失。

这里学习的是 `dX/dσ`。采样更新必须乘每个位置自己的 `Δσ`，不能误用统一的 `Δp`：

\[
\widetilde X_{k+1}=X_k+(\sigma_{k+1}-\sigma_k)\odot v_\theta.
\]

随后执行：

\[
X_{k+1}=M\odot C+(1-M)\odot\widetilde X_{k+1}.
\]

实现使用 `torch.where`。锚点在初始化、每一次更新和最终输出处均得到精确保留，不是只在最后覆盖。

### 6.3 训练与推理仍存在的差别

时间场一致不等于所有状态分布完全一致：训练混合真实动作与高斯噪声，推理使用模型上一步产生的状态，仍可能存在累积误差。当前没有实现 self-forcing 或模型轨迹上的再训练；不能因为时间场相同就宣称消除了全部训练—推理差异。

此外，首轮训练 64 帧、验证也应先用 64 帧；196 帧及流式窗口属于后续长度泛化验证，不能未经验证直接把短片段结果当作完整 HumanML3D 结论。

目前 GloVe 平均条件不编码词序，复杂文本能力预计有限。它能让首轮成本低、对照变量清楚，但不适合用作完整文本动作生成系统的最终结论。如果首轮主要目标变为与 FloodDiffusion 直接比较文本指标，需要再审议更强文本条件；不意味着引入动作编码器。

当前还有辅助目标：由 `X̂0=Xk−σk·vθ` 计算骨长 MSE 和相邻帧速度 MSE，原型权重分别 0.05、0.02。这些损失不能保证严格骨长或物理可行性，而且会改变纯流匹配目标。建议第一轮保留现有实现观察数值稳定性，后续对照必须统一设置；若要证明纯时间场贡献，另做辅助损失的消融。

## 8. 零误差保证的边界

可保证的是：模型所采用的 FP32 动作坐标中，指定控制点在所有采样步骤与输入 FP32 值完全相等。

不能据此保证：

- 给定控制是否满足骨长、关节角、速度和接触限制；
- 未指定关节是否自然、是否存在脚滑、穿地或自碰撞；
- 后续平滑、重定向到另一骨架、IK 或压缩保存后仍保持原控制点；
- 文本语义正确、多样性充分、达到真实条件分布；
- 任意未来控制点都能在零等待的因果系统中被提前满足。

最终控制指标必须从模型直接生成的 XYZ 上计算。评测用 XYZ→263 转换包含几何坐标规范化，只用于嵌入质量指标，不能在该转换后的坐标中替代原始控制误差测量。

## 10. 评测方案：控制、质量、物理表现与速度

### 10.1 控制与重建诊断

| 指标 | 定义与解释 |
|---|---|
| Anchor mean/max error | 控制点 XYZ 欧氏距离，单位米；均值和最大值都报告 |
| 1 mm success | 控制点距离不超过 1 mm 的比例 |
| All-step exact check | 每个采样步比较控制坐标是否完全相等 |
| Free-joint MPJPE | 未控制关节相对参考动作的误差；仅作条件重建诊断，不把与参考不同一概视为生成失败 |
| Bone-length MAE | 与参考动作逐帧骨长比较，单位米；后续增加与统一骨架骨长的比较 |
| 加速度/jerk | 指明差分、FPS、单位和聚合方式，不与定义不明的论文数值混用 |

建议正式控制集分别包含单关节中间帧、稀疏随机关节帧、完整关键帧和流式干净前缀。控制强度及时间位置分组报告，避免总均值掩盖难例。首轮只测一种随机稀疏控制布局，不能覆盖全部场景。

### 10.2 FloodDiffusion / HumanML3D 的质量指标

按官方评测权重计算 FID、R-Precision@1/2/3、Matching score / MM-Dist、Diversity。R-Precision 的检索组大小为 32，正式 Diversity 使用 300 对样本。

这些预训练动作/文本编码器只在评测阶段使用，不在生成网络或训练损失中使用。论文里的 MM-Dist 是文本—动作嵌入距离，不是同一个提示多次采样的 multimodality 指标。

XYZ 模型输出不能直接送给要求 263 维输入的评测器。因此已编写确定性转换适配器，借用 HumanML3D 官方骨架 IK 和特征构建代码，省略骨架重定向以免隐藏骨长误差。此转换尚未完成真实数据验证，必须测量转换误差底线。

计划同时报告：

1. 生成 XYZ→263 与真实 XYZ→263 的指标；
2. 生成 XYZ→263 与官方原始 263 特征的指标；
3. 真实 XYZ→263 与官方原始 263 的转换基线。

若转换出现非有限数值，完整报告失败数，禁止静默过滤失败样本后只展示更好的 FID。若转换基线偏差明显，先修复评测适配，不把这些数字与论文表格直接比较。

首轮 64 个验证样本的 FID 样本量不足、估计偏差大，只用于检查评测管线是否通畅；不会当作质量结论或 SOTA 结果。

### 10.3 BABEL 的 PJ/AUJ

论文描述在动作过渡上评估 Peak Jerk 和 Area Under Jerk，但本次公开仓库未找到对应实现。原型已经能计算 SI 单位的全片段 jerk 峰值及均值曲线积分，**这些不是已经复现的论文 PJ/AUJ**。

正式复现前需确认过渡窗口、差分采样率、关节聚合及归一化。不能把自己的全序列 jerk 值直接标成论文的 PJ/AUJ。BABEL 此项应独立报告协议差异，必要时以明确自定义指标作为补充。

### 10.4 实时性

当前实现是离线窗口采样器，尚未实现经过验证的流式队列。离线 batch FPS 不能当作实时 FPS。

后续流式实验必须明确：窗口与历史长度、已知未来控制范围、允许前瞻、每次输出帧数、每帧网络求值次数、首帧延迟和持续输出延迟。已经输出的帧不能回改；不在已知范围内的未来控制不能用于当前推理。

测时需要 CUDA 同步和 warm-up；报告 batch=1 的首帧、p50/p95 发射延迟和持续帧率。20 FPS 的更新周期为 50 ms；达到离线平均 20 FPS 不等于所有更新在 50 ms 内完成。
